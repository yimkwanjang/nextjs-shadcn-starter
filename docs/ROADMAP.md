# ROADMAP — 노션 견적서 웹 열람 / PDF 다운로드 (MVP)

> 이 문서는 [`docs/PRD.md`](./PRD.md)를 **개발 실행 순서**로 재구성한 것이다.
> PRD가 "무엇을·왜 만드는가"라면, 이 로드맵은 "어떤 순서로 만드는가"를 정한다.
> 기능 ID(F-01 등)·마일스톤(M1~M3)·리스크(R1 등)는 PRD의 것을 그대로 참조한다.

## 개발 순서 원칙

아래 5단계는 **의존성 순서**다. 각 단계는 앞 단계의 산출물 위에 선다.
바깥에서 안으로가 아니라 **뼈대 → 공통 토대 → 핵심 흐름 → 부가 → 다듬기** 순이다.

| 단계 | 이름 | 한 줄 요약 | PRD 대응 |
|:---:|------|-----------|---------|
| 1 | 프로젝트 초기 설정 (골격 구축) | 라우트·경계·데이터 소스 뼈대와 **노션 API 실측** | M1 |
| 2 | 공통 모듈/컴포넌트 개발 | 타입·파싱·계산·캐시·공통 UI (모든 기능의 토대) | M1 후반 |
| 3 | 핵심 기능 개발 | "노션 입력 → 클라이언트 PDF 수령" 완주 경로 (Must F-01~F-14) | M2·M3 |
| 4 | 추가 기능 개발 | 즉시 갱신·열람 로그·면세·로고 등 (Should/Could) | PRD 12절 1단계 |
| 5 | 최적화 및 배포 | 성능·보안 최종 점검·배포·지표 측정 | M3 릴리스 + 이후 |

> **MVP 절취선**: 1~3단계 + 5단계의 **배포 부분**까지가 MVP(3주)다.
> 4단계와 5단계의 최적화 부분은 첫 고객 전달 **이후**(PRD 12절 1단계, MVP+4주)로 미룬다.
> 일정이 밀리면 R10 원칙대로 4단계부터 잘라낸다 — 단 F-09·F-10·F-13은 예외 없이 필수.

## 1단계 — 프로젝트 초기 설정 (골격 구축)

> **왜 먼저인가**: 데이터 소스·보안 경계·라우트 뼈대가 없으면 이후 작성하는 모든 코드가
> 공중에 뜬다. 특히 **노션 API는 학습 데이터와 다를 수 있어**(AGENTS.md, PRD 10.4·R1)
> "조회 1건 성공"을 **가장 먼저** 확인해야 나중의 연동 재작업(일정 +3~5일)을 막는다.
> 문서 확인 전에는 연동 코드를 쓰지 않는다.

### 할 작업

1. **노션 스키마 확정**(PRD 8.1) — `견적서` DB / `견적품목` DB(relation)를 실제 워크스페이스에 생성.
   선결 조건 Q-1·Q-2·A-4 반영.
2. **환경변수 설계**(PRD 10.5) — `NOTION_TOKEN`·`NOTION_QUOTES_DB_ID`·`NOTION_ITEMS_DB_ID`·
   `ADMIN_PASSWORD_HASH`·`SESSION_SECRET`·`NEXT_PUBLIC_SITE_URL`. `.env.local`이 `.gitignore`에
   있는지 확인. `NEXT_PUBLIC_` 접두사는 민감정보 금지.
3. **라우트 뼈대 생성** — 빈 페이지라도 먼저 만든다:
   - `src/app/q/[token]/page.tsx` (공개 뷰, **라우트 그룹 밖**)
   - `src/app/(app)/dashboard/quotes/page.tsx` (내부 목록)
   - `src/app/(auth)/login/page.tsx` (로그인)
4. **nav-config 불변식 지키기**(CLAUDE.md) — `mainNav`에 `{ title: "견적서", href: "/dashboard/quotes" }`
   추가 시 **동시에** 위 `page.tsx`와 `routeLabels.quotes = "견적서"`를 넣는다.
   링크만 있고 페이지 없으면 전체 화면 404가 난다.
5. **`src/proxy.ts` 골격**(Next 16, `middleware.ts` 아님) — 내부 라우트 낙관적 세션 검사 뼈대.
6. **`src/lib/notion/` 경계 생성** — `client.ts` 최상단에 `import "server-only";`.
7. **노션 API 검증 스파이크**(R1) — 공식 문서(`node_modules/next/dist/docs/` 및 노션 API 문서)로
   `Notion-Version`·DB 조회 엔드포인트·relation 확장·레이트리밋을 **확인**한 뒤,
   견적서 1건을 raw로 조회해 콘솔 출력.

## 2단계 — 공통 모듈/컴포넌트 개발

> **왜 이 순서인가**: 3단계의 공개 뷰·내부 목록·PDF·토큰 발급은 **전부 같은 파싱·계산·캐시·타입
> 위에 선다.** 이 토대를 먼저 만들지 않으면 각 기능이 파싱 로직을 중복하고, `NOTION_TOKEN`
> 경계가 곳곳에서 새기 쉽다. "한 곳에서 조회·계산·태그 관리"가 이 단계의 목적이다.

### 할 작업

1. **타입 정의**(PRD 8.4) — `src/lib/notion/types.ts`에 `Quote`·`QuoteItem`·`QuoteTotals`·
   `QuoteAvailability`·`PublicQuote`·`AccessLogEntry`.
   > 불변식: 공개 라우트는 `Quote`가 아니라 `PublicQuote`만 렌더한다(노션 페이지 ID 노출 금지).
2. **파싱 계층**(PRD 8.2·8.3) — 노션 속성 → 앱 타입 매핑. **결측·이상값을 예외로 던지지 않고**
   `warnings[]`에 담고 표 기준값(0원 등)으로 대체.
3. **단일 조회 함수 + 캐시**(PRD 10.3) — 노션 조회를
   `unstable_cache(fn, keyParts, { revalidate: 60, tags: [quoteTag(token)] })`로 감싼 **한 곳**으로
   단일화. SDK가 Next의 패치된 `fetch`를 안 탈 수 있으므로(R12) `unstable_cache`가 안전.
4. **태그 헬퍼** — `quoteTag(token)` 단일 헬퍼로만 태그 문자열 생성(직접 조립 금지, 함정 3).
5. **금액 계산 모듈**(F-03) — 서버에서 **정수(원 단위)** 계산. `수량×단가` 합 → 공급가액,
   부가세는 **원 단위 절사(내림, Q-4 확정 전까지 기본)**, 합계. 노션 합계는 신뢰하지 않고
   불일치 시 `mismatchWithNotion` 기록.
6. **토큰 유틸**(F-04) — `crypto.randomUUID()` 또는 `randomBytes(16)` base64url(128비트 이상).
7. **가용성 판정**(F-06·F-07) — `QuoteAvailability`를 **렌더 시점**에 재계산(캐시에 넣지 않음).
8. **공통 UI 조각** — `npx shadcn@latest add table badge tabs skeleton` (Base UI, `render` prop 사용).
   `src/app/globals.css`에 **인쇄 CSS**(`@page`·`break-inside: avoid`·`thead` 반복) 작성(PRD 10.2).
9. **오류/폴백 헬퍼**(F-14) — 429 백오프·마지막 성공 캐시 폴백 공통화.

### 예상 소요 시간
**3~4일** (M1 후반 ~ M2 초반)

### 완료 기준
- [ ] 금액 계산 함수가 PRD F-03 예시(합계 1,100,000)를 포함한 대표 케이스에서 정확
- [ ] 파싱이 결측/이상 값을 `warnings[]`로 반환(예외 안 던짐)
- [ ] `src/lib/notion/*`를 **클라이언트 컴포넌트에서 import하면 빌드 실패**(server-only 확인, F-13)
- [ ] 조회 함수가 단일 진입점이고 태그가 `quoteTag()`로만 생성됨

## 3단계 — 핵심 기능 개발 (Must, F-01~F-14)

> **왜 이 순서인가**: 여기가 제품의 존재 이유 — **"노션 입력 → 클라이언트가 PDF를 받는다"** 완주
> 경로다. 2단계 토대가 있어야 각 화면이 얇아진다. 데이터(F-01~03) → 링크(F-04·05) → 뷰(F-08) →
> PDF(F-09) → 안전장치(F-06·07·10·12·13) → 장애 대응(F-14) 순으로 완주선을 먼저 잇고 방어를 채운다.

### 할 작업

**A. 데이터·금액 (M2 전제)**
- F-01 노션 견적서 조회 / F-02 품목 relation 조회(N+1 금지, 배치) / F-03 금액 서버 계산 연결

**B. 공개 뷰 (M2)**
- F-05 `/q/{token}` 토큰 접근(없으면 일괄 404, 열거 방지)
- F-08 반응형(375px 무(無)가로스크롤, 표↔카드, CSS만)
- F-06 만료 화면 / F-07 폐기 410 / 9.3 404·410 — **내용을 HTML 소스에도 미포함**

**C. PDF (M2, 핵심 기술 결정)**
- F-09 브라우저 인쇄 CSS 방식(PRD 10.2 방식 A). 한글 깨짐 리스크 구조적 0.
  화면 전용 요소는 인쇄 제외, 행 페이지 경계 분리 없음.

**D. 내부 화면·발행 (M3)**
- F-04 토큰 발급(Server Action, 이미 있으면 재발급 안 함)
- F-11 내부 목록(`/dashboard/quotes`, 상태·고객사·합계·유효기간·링크·경고 배지)
- F-12 접근 제어 — `proxy.ts` 낙관적 검사 + **데이터 계층에서 인가 재확인**(우회해도 데이터 미반환)

**E. 안전 하한 (릴리스 필수)**
- F-10 색인 차단 3중(robots.txt·noindex 메타·`X-Robots-Tag`) + `Referrer-Policy: no-referrer`
- F-13 빌드 산출물 토큰 grep 0건
- F-14 오류·타임아웃 시 안내 화면 + 마지막 성공 캐시 폴백

## 4단계 — 추가 기능 개발 (Should / Could)

> **왜 나중인가**: 이 기능들은 잘라내도 제품이 성립한다(R10). 핵심 완주 경로가 안정된 **뒤에**
> 얹어야 부가 기능이 핵심의 캐시·보안을 깨뜨리지 않는다. PRD 12절 **1단계(MVP+4주)** 에 해당.

### 할 작업

| ID | 기능 | 주의 |
|----|------|------|
| F-20 | "지금 갱신" 즉시 재검증 | Server Action에서 `revalidateTag(quoteTag(token))` |
| F-21 | 접근 로그·열람 여부 | **별도 Route Handler(비콘)** 로 분리 — 페이지 렌더 경로에서 `headers()`를 읽으면 공개 뷰 ISR이 깨진다(함정 2). IP는 원문 대신 해시 저장(90일, Q-5) |
| F-22 | 링크 복사 토스트 | sonner. 실패 시 URL 텍스트 선택 가능 노출 |
| F-23 | 부가세 면세 처리 | 노션 `과세구분=면세` → 부가세 0원 + "면세" 배지 |
| F-24 | 로고·서명 이미지 | 노션 서명 URL은 만료 서명 URL일 수 있음 — 캐시 HTML에 직접 박지 말 것(PRD 10.4 검증) |
| F-25 | 발행 스냅샷 (Could) | 증빙용. 별도 저장소(A-8) 필요 |

## 5단계 — 최적화 및 배포

> **왜 마지막인가**: 최적화할 대상(완성된 기능)과 배포할 산출물이 있어야 이 단계가 성립한다.
> 조기 최적화는 피한다. **배포 자체는 MVP(M3)에 포함**되고, 성능 튜닝·지표 측정은 그 이후에도 이어진다.

### 할 작업

1. **성능**(PRD 4절) — 공개 뷰 LCP 2.5초 이하(4G 모바일) Lighthouse 측정·개선.
2. **캐시 최종 검증** — `npm run build && npm run start`로 ISR·`revalidateTag` 재확인(R11).
   dev 결과를 신뢰하지 않는다.
3. **보안 최종 점검**(PRD 11절) — 토큰 grep 0건 재확인, 색인 차단 3중, no-referrer,
   `/q/*` 레이트리밋(호스팅 기능), HTTPS·HSTS, 통합 권한을 해당 DB 2개로 제한(R7).
4. **배포**(Q-3) — 호스팅(Node 런타임, A-5) 선택·환경변수 주입·도메인·`NEXT_PUBLIC_SITE_URL` 설정.
5. **지표 측정 착수**(PRD 4절) — M3 이후 2주간 발행 소요시간·열람률·PDF 성공률·한글 깨짐 0건 측정.

### 예상 소요 시간
**2~3일** (배포는 M3 내, 성능·지표는 이후 지속)

### 완료 기준 (릴리스 판정 = Definition of Done)
- [ ] Must F-01~F-14 전부 충족 + M2·M3 실측 산출물 존재
- [ ] **F-09·F-10·F-13은 예외 없이 통과**(제품 목적·되돌릴 수 없는 노출·전면 유출 직결)
- [ ] 프로덕션 배포 완료, 공개 링크가 HTTPS로 열림
- [ ] 성공 지표 측정 시작(기준선 대비 발행 2분·재발행 30초·한글 깨짐 0건)

| 4 | 12절 1단계 (MVP+4주) | 즉시 갱신·열람 로그·면세·로고 |
| 5 | M3 릴리스 + 이후 | 배포·성능·보안 점검·지표 측정 |

> **전체 MVP 일정**: 1~3단계 + 5단계 배포 = **3주(M1~M3)**. 4단계와 성능 튜닝은 MVP+4주 이후.
